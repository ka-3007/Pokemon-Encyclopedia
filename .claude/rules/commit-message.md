# コミットメッセージ作成ルール

コードの修正・機能追加・削除など、リポジトリに変更を加えたときは、作業の締めくくりとして必ずその変更内容のコミットメッセージを作成して提示すること。ユーザーから明示的に頼まれなくても行う。

- **対象は今回の作業で変更した内容のみ**。過去の作業や未コミットの以前の変更が残っていても、それらはメッセージに含めない。
- コミットメッセージは日本語で書く（既存のコミット履歴に合わせる）。
- 1行目に変更の要約を書く。複数の変更を含む場合は、本文に箇条書きで内訳を書く。
- 「何を変えたか」だけでなく、必要に応じて「なぜ変えたか」も含める。
- メッセージを提示するだけでよく、`git commit` の実行はユーザーから指示があった場合のみ行う。
